# حالة تنفيذ المشروع

آخر تحديث: 30 سبتمبر 2026.

## التسليم الحالي

**نموذج M1 التفاعلي ومواصفات أولية قابلة للمراجعة، مع تأسيس تطبيق Next.js.** لا يمثل التسليم اكتمال النظام أو جاهزية الإنتاج، ولا تزال قرارات أعمال ضمن M1 مفتوحة.

| المرحلة                  | الحالة                                                                                                                  |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| M1 — تحليل المنتج وUX/UI | النموذج والمواصفات والرحلات ومصفوفة الصلاحيات وقاموس البيانات جاهزة للمراجعة؛ اعتماد السياسات التشغيلية ما يزال مفتوحًا |
| M2 — الأساس والهيكل      | تأسيس Next.js فقط؛ قاعدة البيانات والهوية وصلاحيات الخادم والتحرير الفعلي لم تبدأ                                       |
| M3 — محرك المؤشرات       | أمثلة حسابية داخل نموذج M1 فقط                                                                                          |
| M4 — دورة القياس         | تدفق تجريبي محلي فقط                                                                                                    |
| M5 — الحوكمة             | سجل إجراءات للمعاينة فقط                                                                                                |
| M6 — التقارير واللوحات   | واجهة نظرة عامة توضيحية فقط؛ لا يوجد تصدير فعلي                                                                         |
| M7 — التكامل والإطلاق    | لم تبدأ                                                                                                                 |

## المنجز

- تطبيق Next.js 16.3.7 وReact 19.3.0 وTypeScript مع ملف قفل للاعتماديات.
- استخدام الشعار المرفق دون تغيير ألوانه أو نسبه، مع اتجاه أخضر وذهبي وافق عليه المستخدم.
- واجهة عربية وإنجليزية تشمل الرئيسية والهيكل والمؤشرات ودورة القياس والموافقات والإعدادات.
- نطاقان للبيانات وثلاث فترات ربع سنوية، مع بقاء الجهة والفترة والدور واللغة أثناء التنقل.
- إنشاء مؤشر مستقل أو مركب عبر أربع خطوات مع تحقق من الحقول والأوزان.
- حفظ مسودة تعريف المؤشر محليًا، مع حفظ روابط وأوزان المؤشر المركب.
- إدخال قياس وحفظه أو إرساله وإعادته واعتماده، وتحديث نسبة التحقيق بعد الاعتماد.
- سجل للإجراءات التجريبية وحفظ محلي للبيانات وإظهار فشل التخزين عند حدوثه.
- فصل حساب المستقل والمركب عن الواجهة، واستبعاد القياسات غير المعتمدة من نتائج الأداء.
- وثائق المواصفات والقرارات ودليل التشغيل.

## التحقق

- نجح بناء الإنتاج عبر `npm run build` مع فحص TypeScript.
- نجحت الاختبارات الأحد عشر عبر `npm run test`.
- لم تظهر أخطاء من التطبيق في سجل صفحة المعاينة النهائية.

### اختبارات القواعد

11 اختبارًا في `tests/domain.test.ts` تغطي:

- الاتجاه الإيجابي والسلبي وتجاوز المستهدف.
- التمييز بين الصفر والغياب ومنع القسمة غير الصالحة.
- استبعاد القياسات غير المعتمدة.
- المتوسط الموزون للمركب، وغياب النتائج الفرعية، والدورات والربط بين جهتين.
- الإرسال والإعادة وإعادة الإرسال والاعتماد.
- اشتراط سبب الإعادة، ورفض انتقالات الحالة غير المناسبة.
- منع إجراء الاعتماد في وضع السفير أو الاطلاع ضمن محاكاة النموذج.
- قفل الفترات السابقة ومنع إعادة اعتماد قياس معتمد.
- رفض أشكال بيانات محلية تالفة.

### الاختبار التفاعلي في المتصفح

- إنشاء مؤشر اختبار مستقل بالاسم والوصف والمالك والسفير والمستهدف.
- إدخال قيمة 81 مع مستهدف 90، وإرسالها ثم إعادتها مع تعليق.
- التحقق من منع الإعادة بتعليق فارغ.
- استكمال القياس وإعادة إرساله ثم اعتماده؛ ظهرت النتيجة المتوقعة **90.0%**.
- إعادة تحميل الصفحة والتحقق من بقاء النتيجة وسجل الإجراءات الخمسة.
- تبديل وضع الاطلاع والتنقل بين الصفحات؛ اكتُشف رجوع الدور إلى الافتراضي وأُصلح باستخدام مزود حالة مستمر في التخطيط الجذري.
- تبديل الجهة والتحقق من الاقتصار على مؤشري الوزارة في نطاقها، واستمرار النطاق أثناء التنقل.
- عرض فترة سابقة مقفلة دون أزرار تعديل.
- فحص الاتجاه الإنجليزي وواجهة الحاسب عند 1440 × 1000، وفحص الهاتف عند 390 × 844.

هذه الاختبارات تثبت سلوك النموذج المحلي؛ لا تثبت صلاحيات خادم أو تكاملًا أو أداءً تحت حمل إنتاجي.

## المتبقي قبل إعلان اكتمال M1

- مراجعة المستخدم لتجربة الواجهات ومسارات العمل.
- حسم قواعد الأعمال والسياسات ذات الأثر على البيانات والموافقات كما في DECISIONS.md.
- تأكيد حدود التخصيص والتكامل والترحيل قبل تقدير التنفيذ التشغيلي.

## أول أعمال M2

1. تحديد بيئة الاستضافة والهوية المتاحة للجهة، ومزود قاعدة البيانات.
2. تصميم مخطط الجهات والوحدات والاستراتيجيات والأهداف والأدوار والإسنادات.
3. إنشاء طبقة وصول إلى البيانات وصلاحيات خادم مرتبطة بنطاق الجهة، دون الوثوق بدور أو معرف جهة يرسله المتصفح.
4. تنفيذ تسجيل الدخول والجلسات وربط هوية المستخدم بأدواره المعتمدة.
5. استبدال التخزين المحلي بعمليات خادم وقاعدة بيانات، مع توفير بيانات اختبار منفصلة.
6. تنفيذ تحرير الهيكل والأهداف ومنع الدورات والروابط غير المسموحة.
7. تنفيذ سجل تدقيق دائم لكل عملية كتابة وتغيير صلاحيات.
8. اختبار محاولات الوصول عبر نطاق آخر، والروابط المباشرة، والطلبات المعدلة، وانتهاء الجلسة.

يحفظ النموذج الحالي مسارًا واضحًا لتجربة المنتج أثناء استكمال هذه المتطلبات؛ لا يُستخدم دور المعاينة أساسًا لصلاحيات النظام الفعلي.
